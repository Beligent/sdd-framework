# Illustrative scope decision — no approval granted

This is a teaching record. No real person made this decision. It has no authority
and must not be used as an implementation gate or copied into `approval_refs` as
though it records real consent.

- Gate illustrated: scope.
- Actual decision: none; example only.
- Human decision-maker/source/date: none; no real authorization exists.
- Fictional scenario role: a product owner would review the team-task behavior.
- Proposed coverage: [REQ-001](../requirements/REQ-001.md) revision 1 and
  [SPEC-001](../specifications/SPEC-001.md) revision 1, including its criteria and
  exclusions.
- Example review scope: create/list/complete, server-side team isolation,
  title constraints, usable errors and keyboard interaction; no new auth/storage
  platform, editing or notifications.
- Snapshot illustration: the linked revision-1 documents in this worked example.
  This is not a retrievable record of actual human approval.

In a real project, record the explicit decision, actual person/source and reviewed
snapshot or commit. An approved scope does not by itself approve an implementation
plan. Material changes to these behaviors/criteria invalidate affected scope
authorization. Retain the historical decision and request only the missing
decision for the changed content.

draft status of these artifacts or authorizes actual coding.
