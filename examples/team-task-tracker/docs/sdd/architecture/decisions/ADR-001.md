# Keep team-task behavior behind host service boundaries

## Context

[REQ-001](../../requirements/REQ-001.md) needs a team-scoped task workflow.
[SPEC-001](../../specifications/SPEC-001.md) fixes HTTP behavior and isolation.
The fictional host supplies identity/membership and durable storage adapters;
the example must not force a database, ORM, auth system or test runner.

## Options considered

| Option | Benefit | Cost or risk |
| --- | --- | --- |
| Put storage and state changes directly in route handlers | Small initial file count | Harder to exercise domain behavior independently and centralize team scoping |
| Small task service using host membership/storage boundaries | One place for team-scoped operations and idempotent completion; isolated tests | Requires explicit host adapter contracts |
| Introduce a separate task microservice | Independent deployment | New operations/integration work with no requirement justifying it |

## Decision and rationale

Propose a small task service called by FastAPI handlers, using the host's
membership resolver and a team-scoped task-store adapter. The React task feature
uses a typed API boundary and local state. No separate service deployment or
new shared-state library is needed for the stated behavior.

The store boundary must support create/list/complete for a given team, stable
IDs and timestamps, deterministic list order and idempotent completion. Adapter
contract tests establish those properties against the host's selected durable
store. An in-memory fake may support isolated tests; it is not persistence
evidence. This decision selects responsibilities, not a database technology.

## Consequences

Handlers can validate transport data and enforce membership without duplicating
domain rules. Tests can separate HTTP/authorization, task behavior and adapter
contracts. Costs are a small explicit interface and the need to verify host
integration in a real repository. Revisit if the host already has an equivalent
task abstraction or its storage semantics cannot meet the contract.

## Decision evidence

No actual decision has been made. [APPR-002](../../approvals/APPR-002.md) shows an
illustrative record covering this proposed revision and
[PLAN-001](../../plans/PLAN-001.md). This ADR remains draft and cannot authorize
implementation.
